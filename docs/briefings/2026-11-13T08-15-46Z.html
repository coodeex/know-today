🚀 Build something ambitious

Autonomous product-engineering control plane

Outcome: Let a small company operate a portfolio of services as one evolving product rather than a set of isolated repositories.

Workflow: A home repo holds durable operating instructions, product context, service topology, engineering standards, and task history; agents plan cross-service changes, implement them in mapped repositories, run the required checks, assemble evidence, deploy through approved authority, and turn production and customer signals into the next work queue.

Connected capabilities: Coding agents, repository maps, worktrees, issue tracking, CI, cloud deployment, observability, product analytics, customer feedback, and a durable skills library.

First meaningful milestone: Complete one customer-facing change spanning a storefront and payments service from a single brief, with the system producing a tested change set and an evidence-backed deployment proposal.

Compute dependency intelligence system

Outcome: Give infrastructure-heavy companies a living view of exposure to accelerator vendors, cloud capacity, CUDA dependencies, resellers, and export-control obligations.

Workflow: Continuously ingest purchase plans, workload inventory, cloud usage, vendor announcements, contracts, and compliance documentation; map dependencies to business-critical services; simulate capacity or vendor disruption; route exceptions to the person with authority; and record outcomes to improve future decisions.

Connected capabilities: Document extraction, agent-led data reconciliation, cloud billing APIs, asset inventory, contract systems, forecasting models, compliance rules, and executive reporting.

First meaningful milestone: Produce a current dependency graph for one model-serving platform that identifies critical Nvidia-, CUDA-, and reseller-linked assumptions alongside their owners.

⚡ Fast builds to try

  • Make a repository topology file: add the paths, purpose, owners, and interfaces of five related repos to AGENTS.md; get an agent-ready map for cross-service tasks.
  • Create a shared agent-context repo: move reusable instructions, checklists, and tool references into one version-controlled location; get one place to improve operational guidance.
  • Run a dependency exposure inventory: ask an agent to list every workload, library, cloud SKU, and procurement plan tied to Nvidia or CUDA; get a concrete starting point for vendor-risk planning.
  • Draft a cross-repo task brief: specify a user change, affected services, acceptance checks, and approved directories; get a compact input that an engineering agent can execute consistently.

⚠️ Caveats

  • Material verification needed: the reported Nvidia resignation, interim appointment, investigation, allegations, and market reaction are unverified claims and should not drive operational decisions without primary confirmation.
  • The multi-repo workflow is a single reported practice, not a benchmark or proof of broad compatibility.
  • Cross-repository autonomy needs explicit authority boundaries, test requirements, dependency awareness, and clear human escalation conditions before it can operate at scale.

🧠 The author's perspective

The author believes that today’s signals align with a future in which capable runtimes, durable instructions, integrations, and appropriate authority let people operate increasingly autonomous software development and company operations: the home-repo pattern provides a concrete foundation for persistent skills and cross-repository context, while explicit repository maps turn isolated coding work into coordinated loops across a product surface. The emphasis on shared operational knowledge supports the idea that agents should retain reusable skills, switch contexts, and act from accumulated decision data, and the compute-supply uncertainty reinforces the need for systems that connect infrastructure visibility, compliance guardrails, escalation paths, and data-driven operating decisions across the whole company.
