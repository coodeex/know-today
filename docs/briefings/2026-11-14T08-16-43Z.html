👀 Keep an eye on

  • Repository crews can triage, implement, test, and merge routine changes when a central orchestrator owns the exception queue and written policy boundaries.
  • Model routing is becoming an operating discipline: use premium reasoning selectively and low-cost long-context models for volume work.
  • Narrated screen recordings plus an output-review rubric can turn an expert workflow into a testable automation specification.
  • Creative suites are moving toward prompt-directed batch production and cross-application agents, making asset operations a workflow-design problem.
  • As visible features become cheaper to reproduce, proprietary data, trusted distribution, integrations, and operational judgment become more valuable.

🧭 What changed

Agent operations now have a credible control-plane pattern

Specialists can work per repository while one orchestrator consolidates status, persists decisions, and escalates only unclear product or policy questions.

Evidence is becoming input to implementation

Screenshots, recordings, acceptance examples, and reviewer commentary give coding agents a richer brief than prose alone and create artifacts for grading.

AI workspaces are becoming connective tissue

In-product sheets, notes, whiteboards, data connections, and business-tool integrations point toward less manual transfer between planning, creative, and execution systems.

💭 Opinions worth testing

Opinion — A single cross-project orchestrator is better than forcing a maintainer to switch among separate repository bots.
Opinion — Durable task and decision storage is essential for long-running agent work because model context is not a reliable system of record.
Opinion — Written project intent should determine autonomous merge safety rather than unconstrained model judgment.
Opinion — Operational corrections are a stronger automation signal than raw AI usage because repeated rework exposes reusable judgment.
Opinion — Recording the reviewer’s acceptance criteria teaches judgment, while recording clicks alone mainly teaches procedure.
Opinion — Feature-level reconstruction is usually more useful than cloning a whole product when it addresses a concrete internal friction.
Opinion — Domain-specific artifact tests should outweigh general leaderboards when choosing a model for visual or interactive work.
Opinion — Creative-platform AI is currently more compelling as ecosystem convenience and batch-production leverage than as unique capability.

Reflection: Define explicit agent authority. Store task state and decision rationale. Capture reviewer rubrics. Benchmark models on real artifacts. Codify recurring corrections into skills.

🔮 Predictions to track

Prediction — Feature implementation costs will keep falling as agents can inspect observable behavior, build narrow implementations, and iterate against a rubric.
Prediction — Competitive advantage will shift toward trusted relationships, proprietary backend capabilities, data, and product judgment rather than surface-level UI.
Prediction — Creative work will increasingly move from direct tool operation to typed delegation, asset generation, and automated variation.
Prediction — Agent crews will improve over time when measured outcomes update governed instructions and reusable operating knowledge.

Reflection: Invest in proprietary workflow data. Measure agent outcomes longitudinally. Build evaluation datasets. Track creative-production revision rates.

🚀 Build something ambitious

Autonomous software portfolio operator

Outcome: Let a small product team operate many codebases with a single, high-signal decision inbox instead of a growing maintenance tax.

Workflow: Repository agents ingest issues and pull requests, classify them against each product’s vision and merge policy, assign implementation work to isolated coding environments, run quality gates, merge approved routine work, and feed exceptions plus outcomes to a portfolio orchestrator.

Connected capabilities: Durable task database, repository APIs, coding agents, isolated execution environments, CI telemetry, policy documents, code review, and a decision-learning layer.

First meaningful milestone: Operate three active repositories from one exception queue with persisted rationale for every escalation and a weekly measure of human interruptions avoided.

Observed-workflow automation factory

Outcome: Convert the highest-friction expert processes into dependable internal automations that preserve the judgment behind the work.

Workflow: Capture a narrated screen recording, extract actions and decision criteria, map available APIs or computer-use steps, generate an implementation, grade outputs against a separate review recording, and continuously improve from corrections.

Connected capabilities: Video understanding, speech transcription, process mining, browser or desktop automation, coding agents, evaluation datasets, connectors, and a quality dashboard.

First meaningful milestone: Automate one recurring operations workflow end-to-end and achieve a documented acceptance rate against an expert-created rubric.

Creative production operating system

Outcome: Turn a campaign brief into on-brand, channel-specific creative variants with measurable learning rather than scattered handoffs.

Workflow: A planner converts goals and source data into a production brief, agents generate and resize asset families, a brand evaluator ranks variants, publishing systems distribute approved work, and performance data updates the next brief.

Connected capabilities: Multimodal models, creative-suite agents, CSV and product-data inputs, brand rubrics, asset libraries, analytics, and publishing integrations.

First meaningful milestone: Produce a complete multi-format asset set from structured campaign data and compare revision time with the existing process.

⚡ Fast builds to try

  • Correction miner: Export a week of agent conversations, tag repeated “send it back” moments, and get a ranked list of workflows worth codifying.
  • Repo vision linter: Write a compact vision.md for one project, then ask a coding agent to flag open work that conflicts with its stated direction.
  • Artifact-based model shootout: Give two models the same screenshots and acceptance rubric, then compare the resulting UI artifacts for fidelity, latency, and cost.
  • Narrated QA capture: Record an expert reviewing five examples of a recurring deliverable, then turn the explanations into a reusable evaluation checklist.

⚠️ Caveats

  • Verify release, pricing, and availability claims independently; several reported capabilities may be previews, transcription errors, or promotional claims.
  • Do not infer hidden backend logic, data, rights, or operational capacity from observable product behavior.
  • Give agent systems explicit authority boundaries, scoped credentials, audit records, and human escalation conditions before they take external actions.
  • Treat model rankings and visual judgments as workload-specific until measured on representative tasks.

🧠 The author's perspective

The author believes that today’s signals align with a future in which software development and company operations become increasingly autonomous through capable runtimes, durable instructions, integrations, data, and appropriate authority. A repository hierarchy with persistent task state, written product boundaries, isolated implementation agents, quality gates, and a central exception queue resembles the planning, implementation, testing, review, and deployment loops required for multi-agent operations. Narrated workflows and reviewer rubrics further support the idea that real-world learnings can become reusable decision data, while model routing and connected work surfaces supply the economics and tools for agents to act across contexts. The growing importance of proprietary workflows, trusted relationships, and feedback loops also aligns with building systems that learn from outcomes and seek human help only when their authority or evidence reaches a meaningful boundary.
