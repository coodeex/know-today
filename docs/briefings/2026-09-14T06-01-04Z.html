👀 Keep an eye on

  • Hierarchical agent teams can give one persistent coordinator the job of dispatching isolated implementation workers across projects.
  • Task-aware routing can assign different model and harness combinations to UI work, planning, and bounded fixes instead of forcing one default model.
  • Interactive visual comparison boards create a useful acceptance artifact for design work that tests alone cannot evaluate.
  • Risk-tiered merge policies make meaningful autonomy practical when authority, validation, and rollback match the change’s blast radius.
  • External support messages can become engineering intake, but only with authentication, audit trails, and clear rules for triggering work.

💭 Opinions worth testing

  • Opinion — Newer models are not necessarily the better default; task-specific evaluation matters more than release recency.
  • Opinion — Human attention spent micromanaging context is less valuable than attention spent on prioritisation and consequential decisions.
  • Opinion — A routing matrix should replace a single-model standard when workloads span planning, UI, implementation, and repair.
  • Opinion — Agent interfaces should foreground exceptions, status, evidence, and decisions while keeping detailed traces available on demand.
  • Opinion — Visual prototypes are a stronger medium than prose for choosing among subjective product and interface directions.
  • Opinion — Guardrails should scale with impact, reversibility, and release exposure rather than apply uniformly to every change.
  • Opinion — Low-risk changes with credible scenario evidence can merit automated merging without line-by-line human review.
  • Opinion — A shared intent and context layer improves coordination across projects more than a collection of independent agent chats.

Reflection: Benchmark representative tasks. Encode routing policy. Require outcome evidence. Tier authority by blast radius. Preserve inspectable traces.

🔮 Predictions to track

  • Prediction — Agent harnesses will increasingly automate context-window management, making manual compaction a monitored configuration rather than a recurring developer task.
  • Prediction — Higher task volume will require delegating coordination itself into domain-level manager agents with explicit capacity boundaries.

Reflection: Instrument context quality. Define coordinator capacity limits. Establish domain ownership. Review routing outcomes monthly.

⚠️ Caveats

  • Reported product behavior, model comparisons, quotas, and validation results are anecdotal and need independent verification.
  • Agent-produced risk ratings and test evidence can be incomplete or self-confirming; test their failure modes before reducing review gates.
  • Repository hooks and cross-channel messages are untrusted inputs that can carry prompt injection, impersonation, credential, and unintended-work risks.
  • A central coordinator can become stale when feedback bypasses it; event propagation and source-of-truth rules are required.

🚀 Build something ambitious

Autonomous product-delivery operating system

Outcome: Let a small company run a continuous product loop from customer signal to deployed, measured improvements without turning founders into agent dispatchers.

Workflow: Ingest authenticated customer reports and product telemetry; cluster and prioritise opportunities; create owned workstreams; dispatch planning, implementation, test, and design agents in isolated workspaces; generate visual acceptance artifacts; apply risk-tiered release policies; deploy reversible changes; collect outcome data into durable decision memory; escalate only blocked decisions or high-impact authority requests.

Connected capabilities: Persistent coordinator, domain managers, coding agents, model router, issue and communications intake, browser or visual-review artifacts, CI/CD, observability, experiment analysis, audit logs, and credential-scoped deployment tools.

First meaningful milestone: Deliver one customer-reported improvement through intake, prioritisation, isolated implementation, scenario evidence, visual approval where relevant, staged deployment, and post-release outcome capture.

Evidence-backed autonomous change factory

Outcome: Increase engineering throughput by automatically releasing reversible, low-blast-radius work while improving the signal available for consequential changes.

Workflow: Classify requests by intent and risk; route work to the most suitable model/harness; require agents to produce stated intent, affected systems, scenarios, evidence, and omitted checks; run independent review and live validation when required; merge or deploy under policy; monitor regressions; automatically roll back within defined thresholds; send exceptions to a human decision queue.

Connected capabilities: Repository isolation, task routing, test runners, adversarial review agents, release controls, feature flags, observability, rollback automation, and an evidence ledger.

First meaningful milestone: Autonomously merge and deploy a class of reversible changes with measured scenario coverage, automatic rollback, and a complete audit record.
