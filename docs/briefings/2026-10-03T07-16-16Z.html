AI agents Agent harnesses Developer tools Verification Model routing Cloud coding Workflow skills Connected systems

👀 Keep an eye on

  • Coordinator agents can now group parallel coding work while connected intake systems turn real operational signals into executable tasks.
  • Verification harnesses that let agents run, inspect, fuzz, and retry software are becoming the practical foundation for higher-autonomy development.
  • Persistent assistants are moving from chat windows into email, calendars, messaging, files, and project systems with event-driven behavior.
  • Finite-output decision models offer a cleaner control surface for routing, classification, and policy branches than parsing open-ended agent prose.
  • Model economics increasingly depend on effort settings, output-token consumption, and latency rather than the advertised input price alone.

🧭 What changed

  • Agent work is becoming an operating loop: external signals can enter a coordinator, reach repository agents, and return through tests, diagnostics, and task status.
  • Codebase shape matters more: strict conventions, types, lint rules, and purpose-built CLIs reduce the number of plausible bad implementations.
  • Skills are becoming leaner: compact, deliberately invoked workflow corrections can outperform sprawling prompt manuals when they capture a real recurring failure.
  • Cloud execution expands the working window: coding agents can continue independently of a developer’s active workstation, making runtime controls and auditability central.

💭 Opinions worth testing

  • Opinion — Verification is the highest-leverage capability in agentic development because it gives agents usable feedback instead of making humans relay observations.
  • Opinion — Constraints beat instructions for recurring mistakes: enforce desired structure with architecture, types, linting, registries, and checks.
  • Opinion — Deterministic work belongs in scripts and CLIs, leaving agents to handle ambiguity, product judgment, and diagnosis.
  • Opinion — The engineer’s increasingly valuable job is to shape the runtime, tools, skills, and codebase environment in which agents operate.
  • Opinion — Skills should encode repeated corrections rather than common tasks, because unnecessary instructions consume context without changing behavior.
  • Opinion — Small, user-invoked skills are often more controllable and token-efficient than automatically loaded instruction libraries.
  • Opinion — Sampling representative agent output and correcting systemic causes scales better than manually inspecting every change.
  • Opinion — A lower-priced model is not automatically cheaper when high-effort settings materially increase tokens and task time.

Reflection: Build executable verification. Extract deterministic steps into CLIs. Mine repeated corrections into constraints. Measure full task economics. Sample output quality.

🔮 Predictions to track

  • Prediction — Agent skills will become smaller and more workflow-focused as stronger models need less embedded procedural detail.
  • Prediction — Formal methods and agent-oriented languages will gain attention where correctness can be demonstrated programmatically.
  • Prediction — Persistent assistants will compete chiefly on integration coverage, model quality, operational trust, and price.
  • Prediction — Wider access to very-large-output models will create new code and document workflows, but headline capacity will need independent testing.

Reflection: Keep skills modular. Track verification tooling. Preserve integration portability. Benchmark long-output workloads.

🛠️ Practical workflows

  • Build the outer-to-inner loop: ingest a bug report or customer signal, de-duplicate it, validate it against the product, create a scoped coding task, then attach test evidence to the result.
  • Turn agent transcripts into runtime improvements: collect repeated interventions, cluster them, and convert the recurring causes into tests, lint rules, utilities, or concise skills.
  • Use constrained decisions for routing: define a finite set of outcomes, an abstention state, confidence thresholds, and explicit escalation conditions for high-volume workflow branches.
  • Evaluate models at task level: compare quality, elapsed time, tool use, output volume, and total cost at the exact effort setting your system will deploy.

⚠️ Caveats

  • Several product capabilities, prices, benchmark results, and availability claims need independent verification before they shape a roadmap.
  • Connected email, messaging, calendar, and file workflows raise material data-access, prompt-injection, privacy, and authority-design questions.
  • Anecdotal autonomous-merging and high-throughput claims do not establish reliability for a different codebase, domain, or risk profile.
  • Informal feedback may suit low-stakes skill iteration but does not replace rigorous evaluation for security-sensitive or consequential actions.

🚀 Build something ambitious

Autonomous product-quality command center

Outcome: A product team gets a continuously improving queue of verified customer problems, not a stream of disconnected tickets.

Workflow: The system absorbs support, email, calendar, and issue signals; identifies duplicates and urgency; reproduces candidate bugs against the live development environment; assigns specialized agents to diagnose and implement; runs browser and system verification; and feeds accepted results back into an evidence-rich product-quality dataset.

AI capabilities and tools: Connected intake, finite-output triage, repository agents, browser automation, traces, test runners, issue management, model routing, and a durable memory of prior failures and fixes.

First meaningful milestone: Ship a loop that turns one class of incoming bug report into a reproduced issue with a linked diagnostic trace and a tested proposed change.

Company operating runtime for agent-led delivery

Outcome: A small team coordinates research, engineering, customer operations, and growth through persistent agents that own bounded outcomes and ask for help when real-world judgment or authority is required.

Workflow: Event-driven agents monitor work systems, convert company goals into plans, delegate implementation to specialist loops, measure results, retain reusable skills, update operating context, and escalate only decisions outside their defined authority.

AI capabilities and tools: Persistent assistants, cloud coding agents, shared task memory, communications and calendar integrations, analytics, deployment systems, decision APIs, evaluation harnesses, and scoped credentials.

First meaningful milestone: Operate a weekly product cycle in which agents assemble customer evidence, propose a prioritized plan, deliver tested changes, and publish an outcome summary with escalation requests.

Agent-native engineering platform

Outcome: Teams make autonomous coding faster and safer by turning their accumulated engineering judgment into an executable environment.

Workflow: The platform observes failures and review corrections, converts repeatable mechanics into CLIs, enforces architectural paths through machine checks, dispatches parallel agents, and uses sampled outcomes to improve the harness over time.

AI capabilities and tools: Coordinator agents, code intelligence, AST transforms, linting, types, browser testing, fuzzing, trace capture, task-level cost telemetry, and workflow-skill management.

First meaningful milestone: Automate a recurring refactor or UI-regression category from task creation through verified pull request while capturing every manual correction as structured learning data.

⚡ Fast builds to try

  • Make an agent correction miner: export a week of coding conversations and label repeated “send it back” moments; get a shortlist of candidate rules, tests, and skills.
  • Make a browser evidence CLI: wrap app launch, a critical user journey, screenshots, console logs, and trace collection in one command; get agent-ready verification artifacts.
  • Make a finite ticket router: define explicit support-ticket outcomes plus an abstain option and run a constrained classifier; get cleaner routing data than free-form summaries.
  • Make a task-cost scoreboard: run the same coding task across two models and effort settings; get a practical view of quality, latency, tokens, and total cost.

🧠 The author's perspective

The author believes that today’s signals align with a future in which software development and company operations become increasingly autonomous through capable runtimes, durable instructions, integrations, data, and appropriate authority. Coordinator agents, persistent cross-system assistants, cloud coding, finite decision interfaces, and connected intake loops all point beyond isolated chat tasks toward systems that can observe work, plan, delegate, execute, and learn from outcomes. The emphasis on executable verification, structured constraints, reusable skills, and evidence-bearing workflows supports the author’s view that autonomy depends on a harness around general-purpose agents: one that encodes real operating practice, gives agents useful tools and access, preserves decision data, and creates clear conditions for asking people to handle the parts of the world that still require them.
